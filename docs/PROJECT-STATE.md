# وضعیت جاری پروژه

آخرین به‌روزرسانی: ۱۴۰۵/۰۷/۰۵ (2026-09-27)

## مرحلهٔ فعال

`فاز ۰ — تثبیت نقشهٔ محصول و آماده‌سازی طراحی داشبورد`

## آنچه انجام شده

- هدف محصول و نقش سه بازوی موجود ثبت شد.
- نیاز انتشار چندکاناله از طریق سایت‌ها، بات‌ها و کانال‌ها ثبت شد.
- هر سه مخزن مرجع به‌صورت read-only و روی آخرین commit موجود بررسی شدند.
- مرز توانایی فعلی پروژه‌های مرجع با نیازهای پلتفرم جدید مشخص شد.
- بستهٔ حافظهٔ پروژه شامل راهنمای عامل، نقشهٔ محصول، معماری، Roadmap، UI/UX و امنیت ایجاد شد.

## تصمیم‌های تثبیت‌شده

- محصول جدید یک UI مشترک روی سه بک‌اند نیست؛ یک هستهٔ مرکزی (Control Plane) دارد.
- UIهای سه پروژهٔ مرجع استفاده نمی‌شوند.
- داشبورد اصلی ابتدا با دادهٔ Mock قراردادی ساخته و با نظر مالک محصول تثبیت می‌شود.
- پس از تأیید داشبورد، فرانت و بک‌اند به‌صورت عمودی و مرحله‌ای توسعه پیدا می‌کنند.
- امنیت در طراحی از ابتدا لحاظ می‌شود؛ تست نفوذ جامع در فاز بلوغ بک‌اند انجام خواهد شد.
- سایت و بات هر دو نوعی مقصد انتشارند و باید زیر یک مدل انتشار چندکاناله قرار بگیرند.

## محدودیت‌ها و ابهام‌های باز

- نام تجاری و هویت بصری محصول هنوز تعیین نشده است.
- شبکه‌های اجتماعی نسخهٔ اول هنوز انتخاب نشده‌اند؛ Telegram محتمل است ولی قطعی نیست.
- مدل تأیید انتشار (کاملاً دستی، نیمه‌خودکار یا خودکار) باید در طراحی جریان‌ها قابل تنظیم باشد.
- ساختار استقرار (محلی، سرور اختصاصی یا SaaS) هنوز تصمیم نهایی ندارد.
- روش هویت کاربران و سازمان‌ها هنوز انتخاب نشده است.

## قدم بعدی دقیق

یک Design Brief برای صفحهٔ اصلی داشبورد بساز و سپس یک نمونهٔ فرانت RTL با دادهٔ Mock قراردادی پیاده‌سازی کن. پیش از گسترش به صفحات دیگر، جهت بصری، چگالی اطلاعات و حس newsroom باید توسط مالک محصول تأیید شود.

## معیار پایان فاز ۰

- ساختار اطلاعات داشبورد مشخص باشد.
- سناریو و دادهٔ Mock صفحهٔ اصلی ثبت شده باشد.
- یک جهت بصری قابل مشاهده ارائه شده و بازخورد مالک محصول گرفته شده باشد.
- تا زمان تأیید، بک‌اند محصول جدید یا صفحات فرعی ساخته نشوند.
