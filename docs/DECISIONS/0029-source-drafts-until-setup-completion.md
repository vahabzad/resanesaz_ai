# ADR-0029 — منابع پیش‌نویس تا پایان راه‌اندازی

وضعیت: پذیرفته‌شده و پیاده‌سازی‌شده — 2026-10-28

## تصمیم

- «ذخیرهٔ پیش‌نویس منابع و ادامه» ردیف‌ها را با وضعیت `draft` در scope همان Media ثبت می‌کند؛ پیش‌نویس‌ها پس از رفرش بازیابی و تا پایان wizard قابل حذف‌اند.
- `DELETE /api/v1/media/source-access-requests/:id` مجوز حذف منبع و عضویت همان Media می‌خواهد. حذف منطقی با وضعیت `withdrawn` و audit انجام می‌شود؛ ردیف از فهرست ادمین و سوپر ادمین کنار می‌رود. درخواست بررسی‌شده یا رسانهٔ تکمیل‌شده از این مسیر حذف نمی‌شود.
- ذخیرهٔ مرحلهٔ آخر، تکمیل Media و تبدیل پیش‌نویس‌های باقی‌مانده به `pending` را اتمیک انجام می‌دهد. ایجاد/حذف منبع و تکمیل راه‌اندازی، ابتدا همان ردیف Media را قفل می‌کنند؛ نتیجهٔ درخواست هم‌زمان قابل تکرار است و منبع حذف‌شده ارسال نمی‌شود. ثبت دوبارهٔ پایان راه‌اندازی رویداد ارسال تکراری نمی‌سازد.
- صف Platform علاوه بر کنارگذاشتن `draft` و `withdrawn`، راه‌اندازی کامل رسانه را کنترل می‌کند. endpoint بررسی مستقیم هم تا پیش از تکمیل مجاز نیست؛ پنهان‌کردن ردیف فقط رفتار UI نیست.
- برای سازگاری با دادهٔ موجود، `pending`های رسانهٔ ناتمام در API ادمین «پیش‌نویس» دیده می‌شوند و قابل حذف‌اند؛ در صف Platform دیده نمی‌شوند. تصمیم یا کراولر قبلاً ساخته‌شده عقب‌گرد نمی‌شود.
- پس از تکمیل، Media به وضعیت راه‌اندازی‌نشده برنمی‌گردد. درخواست تازهٔ رسانهٔ تکمیل‌شده مانند قبل مستقیم `pending` می‌شود.
- ستون status از نوع text است؛ این تغییر migration ساختاری و پاک‌سازی دادهٔ فعال ندارد.

کنترل تکرار پس از بازبینی مالک محصول به همان Media محدود شد: ثبت URL معادلِ ردیف حذف‌نشده با 409 رد می‌شود، حتی در دو تب هم‌زمان. Media دیگر آزاد است؛ ردیف withdrawn نیز مانع ثبت تازه نیست. تکمیل wizard پیش از ارسال، ردیف‌های تکراری قدیمی را کنترل می‌کند و از ادمین می‌خواهد مورد اضافه را حذف کند؛ دادهٔ موجود خودکار پاک نمی‌شود.

پیش‌نویس از طریق PATCH همان مسیر با مجوز source/update قابل ویرایش است؛ منبع جدید ساخته نمی‌شود. ویرایش نوع/URL/دسته، اعتبارسنجی کاتالوگ و کنترل تکرار و قفل Media را رعایت می‌کند. تغییر URL، sourceUrls سیاست‌های فعال همان Media را اتمیک اصلاح و revision آن‌ها را افزایش می‌دهد تا انتخاب سردبیر به لینک قدیمی نماند.

## بررسی

آزمون حافظه‌ای API ماندگاری پیش‌نویس، حذف scoped، رد کاربر بدون مجوز/نشست، سازگاری pending قدیمی، بسته‌بودن صف و بررسی Platform پیش از تکمیل، ارسال یک‌بارهٔ نهایی، باقی‌ماندن حذف‌ها و هم‌زمانی حذف/تکمیل را پوشش می‌دهد.
