# ADR 0006 — اتصال بازوی CrawlerGenerator

## وضعیت

پذیرفته‌شده — 2026-09-28

## زمینه

منابع اصلی رسانه از صفحهٔ وب دریافت می‌شوند و برای هر سایت ممکن است به کشف ساختار، ساخت recipe، اجرای مرورگر و استخراج صفحهٔ خبر نیاز باشد. این توانایی از قبل در مخزن مستقل `CrawlerGenerator` وجود دارد و نباید منطق یا UI آن مستقیماً در هسته کپی شود.

## تصمیم

- `CrawlerGenerator` بازوی اصلی منابع وب است و پشت adapter سمت سرور با قرارداد نسخه‌دار فراخوانی می‌شود.
- مرورگر پنل هرگز مستقیماً به API این بازو وصل نمی‌شود؛ هسته مالک احراز هویت، `mediaId`، صف اجرا، deduplication، audit و ذخیرهٔ Raw Article است.
- در اولین اجرای یک منبع، هسته وجود crawler تولیدشده را بررسی می‌کند و در صورت نبود آن `POST /api/generate` را با `listingUrl` فراخوانی می‌کند.
- اجرا با `POST /api/sites/:siteId/run` انجام و سپس فهرست و جزئیات خبرها از endpointهای articles خوانده می‌شود.
- خروجی شامل متن، HTML خام، تصویر، دسته‌ها، برچسب‌ها و نویسنده به‌عنوان ورودی نامطمئن ذخیره می‌شود. HTML پیش از نمایش آینده باید sanitize شود.
- provenance هر خبر شامل adapter، شناسه و نسخهٔ crawler، فایل خروجی، نسخهٔ قرارداد و Crawl Run است.
- RSS فقط adapter اختیاری برای منبعی است که عمداً RSS انتخاب شده؛ مسیر پیش‌فرض ساخت منبع نیست.
- مهلت اجرای adapter ۶۰ دقیقه و تشخیص worker رهاشده ۹۰ دقیقه است، چون crawl مرورگری کامل همراه retryهای هر مقاله می‌تواند زمان‌بر باشد.

## پیامدها

- بهبود crawler مستقل از Control Plane باقی می‌ماند و قرارداد API مرز دو پروژه است.
- محیط اجرا باید بازو را روی شبکهٔ خصوصی/loopback در دسترس هسته قرار دهد؛ API بدون احراز هویت آن نباید عمومی شود.
- خطاهای بازو به error code پالایش‌شده تبدیل می‌شوند و بدنه یا credential خارجی وارد پاسخ پنل و لاگ کسب‌وکاری نمی‌شود.
