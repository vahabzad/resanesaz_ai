# ADR-0014 — قواعد پایهٔ پلتفرم و سرویس تحریریهٔ رسانه

تاریخ: 2026-10-06 — وضعیت: پذیرفته‌شده

با اصلاح دامنه توسط کاربر، تنظیم اصلی تحریریه و تعریف جناح‌ها به Platform Admin منتقل شد. فرم سیاست آزاد Media حذف و endpoint قدیمی نوشتن آن ممنوع شد. مسیرهای پیشین ADR-0013 برای نسخه و تأیید حفظ می‌شوند.

- ادمین در `/platform/editorial` قواعد پایه و فهرست جناح‌ها با شناسهٔ ثابت، نام، تعریف دیدگاه و فعال/غیرفعال را در نسخهٔ جدید ثبت می‌کند. Media فقط این تنظیمات را می‌خواند؛ ادمین بدون عضویت رسانه همچنان می‌تواند تنظیم پایه را اداره کند.
- سردبیر (editor) و مدیر/مالک رسانه، سرویس‌های Media خود را ایجاد، ویرایش، حذف قابل بازیابی و بازیابی می‌کنند. خبرنگار و ناظر مجوز مدیریت سرویس ندارند.
- هر سرویس جهت نگارش از کاتالوگ ادمین، شدت جهت‌گیری، طنز و رسمیت ۰ تا ۱۰۰، منابع و دسته‌بندی‌های ورودی دارد. حالت بدون جهت، شدت صفر دارد. جناح غیرفعال یا حذف‌شده برای نسخهٔ تازه قابل استفاده نیست و سرویس باید دوباره تنظیم شود.
- منابع انتخابی باید در Subscription فعال یا Inbox همین رسانه وجود داشته باشند. دسته‌بندی ممکن است برای دریافت آینده به‌صورت دستی تعریف شود. بین فهرست منابع و دسته‌بندی‌ها AND، داخل هر فهرست OR و فهرست خالی به معنی همه است. این قواعد در API ورود خبر نیز اعمال می‌شوند، نه فقط UI.
- ورودی سرویس فعلاً ۵۰ خبر سالم اخیر از Inbox رسانه است؛ خبر قرنطینه یا بدون متن کافی پذیرفته نمی‌شود. انتخاب خبر و ساخت پیش‌نویس دستی است؛ فیلتر سرویس Subscription یا crawler سراسری ایجاد/تغییر نمی‌دهد.
- هر نسخهٔ خبر یک Editorial Policy immutable دارد که snapshot نسخهٔ تنظیمات ادمین، تعریف جناح، نام/نسخه و تنظیمات سرویس را نگه می‌دارد. تغییر تنظیمات یا حذف سرویس خبرهای قبلی را تغییر نمی‌دهد. policyهای قدیمی بدون snapshot برای خواندن سابقه حفظ می‌شوند.
- revision سرویس و تنظیمات پایه، ویرایش هم‌زمان را رد می‌کند؛ تغییر و audit اتمیک‌اند. حذف سرویس Soft Delete است، نه حذف نسخه‌ها و منابع Story.

کنترل‌های رنجی فعلاً تنظیم قابل ردیابی برای بازنویسی آینده هستند؛ در این مرحله متنی با مدل بازنویسی نمی‌شود و تأیید دستی ادامه دارد.
