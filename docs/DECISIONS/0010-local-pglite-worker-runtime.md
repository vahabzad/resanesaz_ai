# ADR-0010 — Worker محلی با PGlite

تاریخ: 2026-10-06 — وضعیت: پذیرفته‌شده

## مسئله

PGlite فایل‌محور فقط یک فرایند مالک دارد. API و Worker مستقل نمی‌توانند همان data directory را هم‌زمان باز کنند. Worker قبلی علاوه بر این، مسیر نسبی دیتابیس را از cwd پوشهٔ worker حل می‌کرد و ممکن بود دیتابیس خالی دیگری باز کند.

## تصمیم

در توسعهٔ غیرproduction با `DATABASE_DRIVER=pglite`، Backend API حلقهٔ Worker را پس از listen از `back/worker/src/runtime` اجرا می‌کند؛ منطق worker و API از یک connection استفاده می‌کنند. در PostgreSQL یا production، Worker مستقل همچنان مسیر استاندارد است؛ این استثنا مربوط به محیط محلی است و Worker به Next.js منتقل نمی‌شود.

ورودی Worker مستقل cwd و env را نسبت به ریشهٔ Backend تنظیم می‌کند. برای PGlite بدون بازکردن دیتابیس پیام روش اجرای صحیح می‌دهد و اجرا نمی‌کند. چرخهٔ Worker فوری شروع می‌شود و چرخهٔ بعد فقط پس از پایان قبلی و فاصلهٔ تعیین‌شده آغاز می‌شود؛ خطای یک چرخه باعث توقف دائمی مصرف صف نمی‌شود.

پس از restart محلی، اجراهای running با همان شناسه و correlation به queued بازگردانده می‌شوند. این recovery فقط برای PGlite دارای مالک انحصاری مجاز است؛ در PostgreSQL این کار انجام نمی‌شود تا اجرای Workerهای دیگر بازصف‌بندی نشود.

## پیامد

برای دیدن UI و اجرای crawl در محیط فعلی، فقط Backend و Frontend لازم‌اند. برای deploy مستقل Worker و ظرفیت بیشتر باید PostgreSQL استفاده شود. وضعیت queued مرحلهٔ طبیعی صف‌بندی است؛ Worker آن را به running و سپس نتیجهٔ نهایی تبدیل می‌کند.
