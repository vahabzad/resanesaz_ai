# ADR-0044 — تنظیم ذکر منبع و هویت کانال/پیج

تاریخ: 2026-11-04 · وضعیت: پذیرفته‌شده

دستور ثابت «Attribute to sourceName in the body» اختیار ادمین برای حذف عبارت انتساب را خنثی می‌کرد؛ نام برخی منابع اجتماعی نیز فقط hostname بود. این دستور با سیاست صریح هر سردبیر جایگزین می‌شود.

`SectionSettings.sourceAttribution` دو مقدار مستقل `website` و `social` از نوع `named|omit` دارد؛ نبود فیلد برای سازگاری معادل named/named است. تنظیم در هر دو فرم مدیریت سردبیر، زیر «شیوهٔ ذکر منبع» ارائه می‌شود و در snapshot سیاست کار ثبت می‌گردد. تغییر تنظیمات فقط بر کارهای تازه اثر می‌گذارد؛ صف/خروجی تاریخی بازنویسی نمی‌شود. Migration لازم نیست.

حالت omit معرفی منبع دریافت، دامنه، شبکه و عبارت انتساب کلیشه‌ای را از تیتر/لید/متن/نسخهٔ اجتماعیِ تولیدی حذف می‌کند. گویندهٔ نقل‌قول، انتساب ادعای مشخص و عدم قطعیت حفظ می‌شوند؛ این تنظیم مجوز جعل واقعیت یا تغییر گوینده نیست. اطلاعات منبع و provenance داخلی حذف نمی‌شوند. سیاست صریح بر دستورهای متعارض ذکر منبع در پرامپت نگارش مقدم است؛ قالب ثابتِ اجتماعی که ادمین مستقیم در prefix/suffix می‌نویسد همان رفتار قبلی را دارد.

در صف‌گذاری، هویت اجتماعی از adapter ثابت، URL پروفایل و نام ثبت‌شده استخراج می‌شود. نام معنادار کانال/پیج ترجیح دارد؛ hostname، نام شبکه یا URL به آیدی پروفایل تبدیل می‌شود، برای نمونه «کانال @GizmizTel در بله». نام انسانی کانال حدس زده نمی‌شود. هویت در `input.provenance.editorialSource` snapshot می‌شود. کار قدیمی بدون این فیلد از نام/URL ذخیره‌شدهٔ خودش fallback می‌گیرد. شناسهٔ ویدیو یا مسیرهای پست به‌عنوان نام کانال جا زده نمی‌شوند. دادهٔ هویت مانند متن منبع، دادهٔ غیرقابل اعتماد است و در بخش دادهٔ JSON پرامپت می‌آید.

کنترل در این مرحله از مسیر قرارداد، snapshot و دستور مدل اعمال می‌شود؛ بازنویسی تازهٔ مدل روی خبر واقعی برای بازبینی اجرا نشده است. آزمون واحد هویت/دستور و integration ذخیره/بازخوانی API و حفظ سیاست کار قدیمی اجرا می‌شوند. UI واقعی روی کپی مستقل داده با PATCH واقعی و موبایل ۳۹۰ بررسی می‌شود؛ تنظیمات اصلی ادمین در این بازبینی تغییر نمی‌کنند.
