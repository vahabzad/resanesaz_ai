# ADR-0022 — نقش‌های ادمین، دسترسی منابع و نگاشت دسته‌بندی

وضعیت: پذیرفته‌شده برای بازتنظیم دامنه بر اساس تصمیم جلسه — ۱۴۰۵/۰۷/۲۷

## زمینه

تصمیم محصولی جدید جریان کار را بر دو نقش متمرکز می‌کند: سوپر ادمین و ادمین (سردبیر). ادمین می‌تواند چند رسانه بسازد، اما استفاده از منابع و دسته‌بندی‌ها باید زیر کنترل سوپر ادمین باشد. دسته‌بندی‌های خام پس از کراول منبع دریافت می‌شوند و باید با دسته‌بندی داخلی سامانه معادل شوند.

## تصمیم

- سوپر ادمین ادمین‌ها را ایجاد می‌کند و می‌تواند دسترسی هر ادمین به منابع را اعطا، محدود یا لغو کند.
- ادمین درخواست استفاده از منبع و دسته‌بندی‌های لازم را برای سوپر ادمین می‌فرستد؛ درخواست و تصمیم آن باید ممیزی‌پذیر باشد.
- Source و دسته‌بندی خام آن در Platform scope باقی می‌مانند. نگاشت هر دستهٔ خام منبع به دسته‌بندی داخلی را سوپر ادمین مدیریت می‌کند و هویت/نام خام برای ردیابی حفظ می‌شود.
- هر ادمین می‌تواند چند Media بسازد. در هر Media، منابع و دسته‌ها به‌صورت کلی یا به‌تفکیک منبع انتخاب می‌شوند و این تنظیمات Media-scoped هستند.
- ساخت Media شامل نام/لوگو، منابع/دسته‌ها، دیدگاه تحریریه و سکوهای انتشار است.
- جداسازی فنی `front` و `back`، API نسخه‌دار و مرز Platform/Media تغییر نمی‌کند. نگاشت نقش محصولی به Permission فنی باید در پیاده‌سازی بررسی شود.
- رفتار اتصال سکوها به محتوای آمادهٔ انتشار هنوز تصمیم‌گیری نشده و نباید در این ADR فرض‌سازی شود.

## پیامدها

- مدل/قراردادهای درخواست دسترسی و Category Mapping باید ممیزی شوند و در صورت نبود، با migrationهای افزایشی اضافه شوند.
- رابط ادمین و سوپر ادمین باید وضعیت درخواست، سطح دسترسی و نگاشت دسته‌بندی را جداگانه نشان دهد.
- Mockهای runtime داشبورد حذف می‌شوند؛ دادهٔ fixture فقط برای آزمون باقی می‌ماند.
- پیش از تغییر migration یا حذف پیاده‌سازی، وضعیت دادهٔ محلی و تغییرات ثبت‌نشده بررسی می‌شود.
