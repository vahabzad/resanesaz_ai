# ADR-0020 — سایت داخلی و انتشار اتمیک وب

وضعیت: پذیرفته‌شده؛ 2026-10-14

## تصمیم

فاز چهارم یک Site Builder مبتنی بر تنظیمات اعتبارسنجی‌شده و rendererهای داخلی دارد. هویت، زبان، رنگ، دو چیدمان خبر برجسته/شبکه و حداکثر هشت بلوک مرتب با قواعد Section قابل تنظیم‌اند. الگوی spec و جداسازی draft/preview از مخزن مرجع News-website-builder مطالعه شد؛ UI، فایل‌محوری، تولید و اجرای کد آزاد و processهای آن وارد runtime محصول نشدند. تولید دلخواه کد با AI، اتصال دامنه، DNS و استقرار بیرونی در این gate نیستند.

هر Media چند سایت با شناسهٔ نشانی سراسریِ یکتا و ثابت دارد. سایت `draft/live/paused/archived` و revision مستقل دارد. ذخیره فقط `spec` پیش‌نویس را تغییر می‌دهد؛ `activate` طراحی را در `liveSpec` ثبت و سایت را عمومی می‌کند. توقف یا بایگانی، نمایش عمومی را قطع و کارهای باز همان مقصد را لغو می‌کند. بازیابی به draft است و کار لغوشده خودکار زنده نمی‌شود.

## قرارداد محتوا

Frontend فقط API نسخه‌دار را مصرف می‌کند. آدرس عمومی `/s/:slug`، فهرست تمام خبرها، فهرست Section و `/s/:slug/news/:storyId` از `site_article` می‌خوانند؛ پیش‌نویس و Story آمادهٔ بررسی هیچ‌گاه عمومی نمی‌شوند. homepage، WebCard را با قواعد بخش اصلی/ثانویه و سقف هر بلوک می‌گیرد؛ صفحهٔ کامل WebFull همان snapshot را می‌خواند. پیش‌نمایش احراز هویت‌شده می‌تواند حداکثر ۲۰ نمونهٔ تأییدشدهٔ رسانه را پیش از انتشار نشان دهد. تغییر طبقه‌بندی/متن تحریریه یا طراحی، snapshot خبر منتشرشده را تغییر نمی‌دهد.

job به نسخهٔ دقیق و approval انسانی همان نسخه وابسته است؛ تنها آخرین نسخهٔ approved در زمان enqueue و اجرا پذیرفته می‌شود. snapshot شامل WebCard/WebFull، زبان، بخش‌ها و نام منابع است؛ سیاست و شناسهٔ کاربر منتشر نمی‌شود. تصویر پیش از ثبت با قواعد HTTPS عمومی، DNS/IP و credential بررسی و در صورت نامعتبر بودن حذف می‌شود؛ Backend تصویر را proxy نمی‌کند. متن با React escape می‌شود؛ HTML خام اجرا نمی‌شود. preview داخل iframe بدون اجازهٔ script است و پاسخ‌های preview/public CSP منع script، منع فرم و frame-ancestors محدود دارند. preview خصوصی، no-store و noindex است.

## صف و یک‌بار انتشار

`web_publication_job` با کلید یکتای Media × Site × ArticleVersion، وضعیت `queued/succeeded/failed/cancelled`، scheduledAt دارای timezone، حداکثر سه تلاش و نتیجهٔ مسیر عمومی پایدار ثبت می‌شود. تأخیر زمان‌بندی تنها زمان مجاز شروع است؛ worker قبل از آن کاری اجرا نمی‌کند. retry دستی فوری است؛ تغییر زمان آینده برای کار queued/failed/cancelled با بررسی زمان قبلی، مجوز و تأیید معتبر انجام می‌شود و سقف تلاش را ریست نمی‌کند. صف رسانه حداکثر ۵۰۰ کار باز می‌پذیرد.

تحویل به سایت داخلی فراخوانی شبکه ندارد. قفل Site → Story → Job و بررسی دوبارهٔ membership/approval، نوشتن یا به‌روزرسانی تنها رکورد Site × Story، ثبت نتیجه و audit همگی در یک تراکنش‌اند. بنابراین claim همان قفل تراکنش است و lease یا وضعیت running پایدار لازم نیست؛ قطع فرایند پیش از commit همهٔ تغییرات را rollback و job را queued باقی می‌گذارد. failure تراکنش به خطای پالایش‌شدهٔ `WORKER_FAILED` تبدیل می‌شود. دو worker نمی‌توانند نتیجهٔ تکراری بسازند. نسخهٔ تازهٔ تأییدشده همان URL خبر را با snapshot تازه به‌روز می‌کند؛ مقصدهای دیگر مستقل‌اند.

حلقهٔ انتشار در PostgreSQL داخل worker مستقل و در PGlite توسعه داخل مالک یگانهٔ API اجرا می‌شود. migrationهای محلی پیش از listen از همان اتصال PGlite اجرا می‌شوند؛ اجرای CLI migration هم‌زمان با API لازم و مجاز نیست. migration استقرار PostgreSQL همچنان مرحلهٔ مستقل release است.

## مجوز و آثار

مجوزهای موجود `destination` برای مدیریت سایت و `publication` برای صف استفاده می‌شوند؛ scope از نشست است و ورودی mediaId رد می‌شود. worker مجوز درخواست‌کننده را دوباره کنترل می‌کند. تنها public GET سایت live بدون نشست مجاز است. شبکه‌های اجتماعی و Connection/credential محرمانه در فاز پنج افزوده می‌شوند؛ این فاز هیچ credential خارجی ذخیره نمی‌کند.
