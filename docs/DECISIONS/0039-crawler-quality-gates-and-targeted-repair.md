# ADR-0039 — نمونه‌برداری متنوع، کنترل کیفیت مشترک و اصلاح هدفمند کراولر

تاریخ: 2026-11-03 · وضعیت: پذیرفته‌شده

## تصمیم

قواعد نمونه‌برداری و اعتبارسنجی این سند جایگزین سقف شش نمونه و کنترل حداقلی طول در ADR-0011 هستند. قرارداد Recipe نسخهٔ ۲، خواندن Recipe قدیمی، مرز Front/Backend و رفتار شروع دریافت پس از دیباگ موفق در ADR-0038 حفظ می‌شوند.

ساخت وب ابتدا خانوادهٔ مسیرهای خبر و سپس امضای DOM صفحات را بررسی می‌کند؛ خانواده‌های liveblog، تصویر و چندرسانه‌ای و ابتدا/انتهای هر خانواده اولویت دارند. پیش‌فرض probe برابر ۱۲ و نمونهٔ اعتبارسنجی ۶ تا ۱۲ متناسب با تنوع ساختار است. این روش نمونه‌برداری است، نه تضمین پوشش همهٔ قالب‌های سایت. خطاهای تاریخی و نمونه‌های موفق نسخهٔ مبنا اجباری‌اند. دیباگ تمام لینک‌های فعلی و قبلی کشف‌شده را در سقف هر discovery برابر ۵۰۰ بررسی می‌کند؛ سقف نمونهٔ معمولی، نمونه‌های اجباری را حذف نمی‌کند.

اعتبارسنجی ساخت و runtime از یک تابع استفاده می‌کنند: تطابق عنوان، پوشش متن ساختاریافتهٔ همان خبر، حذف اشتباه متن، آلودگی به پیشنهاد/نظر/تبلیغ، سلامت HTML، دسته‌بندی و خلاصه‌بودن خروجی لایوبلاگ بررسی می‌شوند. تشخیص‌ها شامل مرحله، امکان اصلاح با selector، امضای قالب و مقادیر اندازه‌گیری‌شده‌اند. این کنترل‌ها heuristic هستند؛ نبود متن مرجع کامل یا تغییر قالب می‌تواند نیازمند بررسی انسانی باشد.

اصلاح فقط با شواهد خطا و Recipe قبلی انجام می‌شود. در شکست صرفاً دسته‌بندی، Backend همهٔ فیلدهای دیگر را از نسخهٔ قبلی نگه می‌دارد. نمونه‌های موفق و نشانه‌های پراکندهٔ متن آن‌ها در همان build حفظ می‌شوند؛ افت بیش از ۲۰٪ طول/پوشش نشانه‌ها یا حذف کشف لینک قبلی، regression است. تمام لینک‌های کشف‌شده در تلاش‌های قبلی در baseline باقی می‌مانند. الگوی مؤثر تکراری، خطای شبکه/دسترسی/رندر غیرقابل‌اصلاح با CSS یا اتمام بودجه چرخه را متوقف می‌کند.

بودجهٔ پیش‌فرض: سه تلاش، ده دقیقه کل، ۱۱۰۰ درخواست با احتساب retry و sitemap، کش HTML حداکثر ۶۴ میلیون بایت. envهای `CRAWLER_BUILD_*` در `.env.example` قابل تنظیم و دارای سقف هستند. تعداد زیاد درخواست برای دیباگ پوشش کامل است؛ ساخت معمولی عموماً بسیار کمتر دریافت می‌کند. حداکثر evidence سریال‌شده ۱۸۰ هزار نویسه، حداکثر هشت صفحهٔ اولویت‌دار، و timeout هر درخواست مدل ۱۸۰ ثانیه است. صفحات موفق و خطاهای دریافت در چرخه cache می‌شوند تا اصلاح CSS موجب دریافت مجدد بی‌هدف نشود.

بازسازی منبع دارای نسخهٔ فعال، آن را تا قبولی نسخهٔ تازه غیرفعال نمی‌کند. شکست، لغو یا stalled شدن ساخت/دیباگ نسخهٔ فعال را جایگزین نمی‌کند؛ draft ناموفق وضعیت مستقل دارد. توقف صریح کاربر و archive همچنان مقدم‌اند.

## امنیت و سازگاری

Codex فقط Recipe اعلانی می‌سازد؛ اجرای عادی نیازی به مدل ندارد. sandbox فقط‌خواندنی، ابزارهای shell/app/MCP غیرفعال، شبکه و web search مدل بسته، محیط پالایش‌شده و SSRF guard دریافت Backend حفظ شدند. evidence محتوای فعال، attributeهای اضافی و credential/query لینک‌ها را حذف می‌کند؛ متن وب همواره ورودی نامطمئن است. RSS همچنان با parser واقعی و بدون تولید Recipe مدل کار می‌کند.

فیلدهای تشخیص/بودجه/علت توقف به گزارش نسخه به‌صورت اختیاری اضافه شده‌اند؛ migration دیتابیس و تغییر الزامی در API مصرف‌کننده نداریم. اسکریپت ارزیابی جداگانه دیتابیس محصول را باز نمی‌کند و Source، نسخهٔ فعال و Inbox را تغییر نمی‌دهد.

## اعتبارسنجی

آزمون‌های fixture کنترل کیفیت، تنوع قالب، لایوبلاگ آرشیوی نادر، اصلاح دسته‌بندی بدون تخریب متن، خطای دریافت، بودجه، تکرار بی‌اثر، رگرسیون و استقلال runtime/RSS از مدل را می‌پوشانند. آزمون API حفظ نسخهٔ فعال در شکست/لغو/stall بازسازی را بررسی می‌کند. نتایج اجرای محلی و محدودیت ارزیابی زنده در `docs/CRAWLER-QUALITY-REVIEW.md` ثبت می‌شوند.
